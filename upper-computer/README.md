# MaixCAM Pro 钢球图传上位机

本目录是独立的 Windows 上位机，不修改也不替换 MaixCAM Pro 端的任何文件。它直接兼容当前程序已启用的 WebRTC 服务：

- 信令地址：`ws://<设备 IP>:8001/<客户端 ID>`
- 视频：当前 MaixCAM Pro 程序创建的 320 × 180 H.264 WebRTC 通道
- 实时显示：浏览器硬件解码，通过固定帧率画布稳定显示
- 测试录像：从点击“开始测试并录像”到“结束测试并保存”形成一个完整 WebM 文件
- 自动重连：网络短暂中断后指数退避重连；录像时间轴不中断，并在中断画面中写入 `VIDEO LOST - RECONNECTING`
- 回放：测试历史列表、进度拖动、0.25～2 倍速、前后 5 秒跳转和全屏播放

## 使用环境

1. Windows 10/11。
2. 最新版 Microsoft Edge 或 Google Chrome。推荐 Edge。
3. 电脑和 MaixCAM Pro 连接同一个局域网，电脑能访问设备 IP。
4. MaixCAM Pro 上运行现有工程，启动日志中应打印 WebRTC 播放地址。

浏览器必须通过本目录的本地服务打开，不能直接双击 `index.html`。本地服务使用 `http://127.0.0.1:8765`，因此录像文件选择接口处于浏览器允许的安全上下文。

## 启动

双击：

```text
start.cmd
```

脚本会启动一个仅监听本机 `127.0.0.1` 的静态文件服务，并打开默认浏览器。命令窗口不能关闭；使用完毕后在窗口中按 `Ctrl+C` 停止。

如果浏览器没有自动打开，手动访问：

```text
http://127.0.0.1:8765/
```

## 完成一次测试

1. 输入 MaixCAM Pro 的 IP，例如 `192.168.10.25`，点击“连接设备”。
2. 等待右上角显示“视频已连接”，并确认画面连续。
3. 填写测试名称，点击“开始测试并录像”。
4. 在弹出的保存窗口中选择录像目录和文件名。确认后才正式开始计时和录像。
5. 完成测试后点击“结束测试并保存”，等待“录像已保存”提示。
6. 在右侧“测试回放”中选择本次记录；首次回放时浏览器可能请求该文件的读取权限。

也可以点击“打开视频”回放已经移动、复制或来自其他电脑的 WebM/MP4 文件。

## 录像完整性与稳定性

- Edge/Chrome 下使用 File System Access API，每 1 秒将录像分片直接写入所选文件，不会把长时间测试的全部视频堆在内存中。
- 点击结束后，上位机会先请求最后一个分片、等待全部磁盘写入完成，再关闭文件并加入回放列表。
- 录像来源为 30 FPS 固定媒体轨。WebRTC 抖动不会改变录像容器的测试时间轴。
- 图传断线时继续记录带断线标记的画面，同时后台自动重连，因此不会产生一个看似连续、实际缺失时段的视频。
- 如果浏览器不支持直接写盘，上位机会明确警告，并退化为结束时下载；此模式不适合长时间录像。

建议每次正式试验前先做一次 30 秒预试验，结束后完整回放，并确认设备网络、磁盘剩余空间和保存目录权限正常。

## 常见问题

### 一直显示“设备连接失败”

- 确认设备 IP 正确且电脑能访问它。
- 确认 MaixCAM Pro 的现有程序正在运行，并且没有其他 WebRTC 页面占用连接。
- Windows 防火墙或网络的 AP 隔离可能阻止电脑访问设备的 TCP 8001 端口。

可以在 PowerShell 中检查：

```powershell
Test-NetConnection 192.168.10.25 -Port 8001
```

### 画面清晰度为什么是 320 × 180

这是当前 MaixCAM Pro 代码中 WebRTC 独立摄像头通道的既定分辨率。上位机保持原始比例显示和录像，没有修改设备端配置，也不会通过插值伪造细节。

### 回放列表里有记录但打不开

录像文件可能被移动、改名或浏览器权限被清除。点击“打开视频”重新选择该文件即可回放。录像文件本身不依赖浏览器数据库。

## 开发验证

本目录核心逻辑使用 Node.js 内置测试框架，无第三方依赖：

```powershell
node --check upper-computer/app.mjs
node --test upper-computer/tests/core.test.mjs
```
